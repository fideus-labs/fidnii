# Fidnii Niivue API Surface

Complete catalog of every `@niivue/niivue` symbol, method, property, event, and
field that fidnii touches, captured against the pinned baseline
**`@niivue/niivue@0.68.1`**. This is the input to the
[[migration-map]]: each entry here is cross-referenced there against its
`1.0.0-rc.9` status.

**Conventions**

- All `file:line` references are relative to the `fidnii/` package root (e.g.
  `src/OMEZarrNVImage.ts:856`).
- "Value import" = imported as a runtime value; "type import" = `import type`.
- Generated by exhaustive ripgrep over `src/`, `test-page/`, and `tests/` on
  2026-06-22 (branch `upgrade-deps`).

> **Note on scope.** Several findings below go *beyond* the original task
> checklist — they are flagged with **⚠ Beyond-checklist** so the migration map
> does not miss them. The most important: fidnii consumes **five** Niivue events
> (not three), and `screenFieldOfViewExtendedMM` is deliberately **not** called.

## 5. Niivue events consumed via `addEventListener`

fidnii listens on the `Niivue` instance (it is an `EventTarget`). **Five**
distinct niivue events are consumed (the task list named three):

| Event | `detail` used | Registration | Handler |
|---|---|---|---|
| `clipPlaneChange` | `detail.clipPlane` | `src/OMEZarrNVImage.ts:494-500` (in `create()`, with `AbortController` signal) | `onNiivueClipPlaneChange(e.detail.clipPlane)` |
| `sliceTypeChange` | `detail.sliceType` | `src/OMEZarrNVImage.ts:2311-2317` | `_handleSliceTypeChange(nv, e.detail.sliceType)` |
| `locationChange` | whole `detail` | `src/OMEZarrNVImage.ts:2320-2326` | `_handleLocationChange(nv, e.detail)` |
| `mouseUp` ⚠ | none | `src/OMEZarrNVImage.ts:1838-1845` | `_handleViewportInteractionEnd(nv)` |
| `zoom3DChange` ⚠ | none | `src/OMEZarrNVImage.ts:1847-1853` | `_handleViewportInteractionEnd(nv)` |

⚠ `mouseUp` and `zoom3DChange` are **Beyond-checklist** — they must exist with
the same names in 1.0 or viewport-interaction tracking silently stops firing.

All registrations use `{ signal }` from an `AbortController` for teardown
(`src/types.ts:299` documents the controller). The handlers assume the
browser-native `CustomEvent`-style `detail` payload (`EventTarget` model), **not**
`onClipPlaneChange`-style callback props — a key axis for [[events]].

## 7. `NVImage` subclass surface — `OMEZarrNVImage extends NVImage`

The highest-risk migration area: fidnii **subclasses** `NVImage` and reaches into
its private/protected fields. See [[nvimage-api]] for the 1.0 deltas.

### 7.1 Class & constructor

- `export class OMEZarrNVImage extends NVImage` — `src/OMEZarrNVImage.ts:99`.
- `super()` — `src/OMEZarrNVImage.ts:352` — **no-argument** super constructor
  call (relies on `NVImage` supporting a no-arg/empty construction).
- `private readonly niivue: Niivue` — `src/OMEZarrNVImage.ts:142` (stores the
  attached instance; not an `NVImage` field).

### 7.2 Overridden members

- `override get colormap(): string` — `:126-128` — returns `this._colormap`.
- `override set colormap(cm: string)` — `:130-139` — calls `super.colormap = cm`
  (comment: NVImage's setter "calls calMinMax + onColormapChange"), then
  propagates `cm` to every slab NVImage. Depends on `NVImage` exposing a
  **settable** `colormap` accessor and the `_colormap` backing field.

### 7.3 Inherited `NVImage` methods called

| Method | Call sites | Notes |
|---|---|---|
| `calculateRAS()` | `:994`, `:3162` | Called after writing `hdr.affine/dims/pixDims` to rebuild RAS transforms. |
| `setColormapLabel({ R, G, B, A, I, labels })` | `:1178` | Called on a **slab** NVImage with a `ColorMap`-shaped object (label images). |
| `calMinMax()` | **not called directly** | fidnii depends on NiiVue invoking it inside `updateGLVolume()`/`refreshLayers()`. Comments at `:131,845-847,3050,3200-3201` document this contract; fidnii brackets those calls by resetting `global_min` and widening `cal_min/cal_max`. |

### 7.4 Direct field access on `NVImage` (`this.*` and on slab `nvImage.*`)

| Field | Access | Call sites |
|---|---|---|
| `hdr` | read + write | write `:532,2653`; read/mutate sub-fields `:910,919,923,991,1113,1128-1129,3081,3099,3101,3154,3161,3169,3181-3182`. |
| `hdr.affine` | write | `:991,3154`. |
| `hdr.pixDims` | write | `:919,3099`. |
| `hdr.dims` | write | `:923,3101`. |
| `hdr.sform_code` | write | `:3161`. |
| `hdr.cal_min` / `hdr.cal_max` | write | `:1128-1129,3181-3182`. |
| `img` | write | `:580,827,1620` (`this.img = … as NVImage["img"]`). Uses the `NVImage["img"]` indexed type. |

> `NVImage["img"]` etc.). The `hdr` NIfTI header shape (`affine`, `pixDims`,
> `dims`, `sform_code`, `cal_min/max`) must also remain stable. All flagged for
> the migration map's Risk Hotspots.

## 8. Enum value dependencies (`SLICE_TYPE` / `DRAG_MODE`)

Beyond imports (§1), fidnii depends on specific **values** and reverse-lookups:

- `SLICE_TYPE.AXIAL`(0), `.CORONAL`(1), `.SAGITTAL`(2), `.RENDER`(4),
  `.MULTIPLANAR` — used as switch cases and comparisons:
  `src/ViewportBounds.ts:221-336`, `src/OMEZarrNVImage.ts:1993-1994,2406,2414-2416,2439-2445`,
  `test-page/main.ts:397-401`.
- Reverse lookup `SLICE_TYPE[n]` (numeric → name string):
  `src/OMEZarrNVImage.ts:2633,2671,2958`; `test-page/main.ts:336`. Requires
  `SLICE_TYPE` to remain a **reverse-mappable** enum-like object (a plain
  `as const` object would break `SLICE_TYPE[n]`).
- `DRAG_MODE.pan`, `DRAG_MODE.contrast` — `test-page/main.ts:418-419`.

See [[enums-and-exports]] for 1.0 enum shape / import-location changes.

## 9. Summary of risk-ranked hotspots (feeds [[migration-map]])

1. **`NVImage` subclassing + private fields** (`_colormap`, `_opacity`, `img`,
   `hdr.*`, `global_min/max`) — §7. No type safety; silent breakage risk.
2. **`nv.scene` direct mutation** (`crosshairPos`, `clipPlaneDepthAziElevs`) — §3.
3. **Event payload model** (5 events, `EventTarget`/`detail` shape) — §5.
4. **Rendering backend** (WebGPU vs WebGL2) affecting `nv.canvas`, async
   `attachToCanvas`, headless Playwright — §2/§4, see [[rendering-backend]].
5. **Enum reverse-lookup** `SLICE_TYPE[n]` — §8.
6. **Replicated FOV math** depending on `pan2Dxyzmm`/`volScaleMultiplier`
   semantics (since `screenFieldOfViewExtendedMM` is intentionally bypassed) — §2.
